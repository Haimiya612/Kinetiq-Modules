# Kinetiq Unified Modules · Batch 07A

One repository **cataloguing eight sources** while preserving the existing Kinetiq
video ZIP install contract. The upstream code/assets/binaries are **not copied**
into this repository; upstream-published SHA-256 strings and download URLs are
referenced. This avoids unauthorized redistribution and preserves upstream updates.

## Import in Working Copy (iPhone)

1. Copy this ZIP's **contents** (not its outer folder) into the root of the
   existing `Haimiya612/Kinetiq-Modules` checkout. **Keep the existing `modules/`
   folder and ZIPs**; don't delete it. The included `repository.json` already
   lists **43 video ZIP candidates** (your 3 plus 40 upstream references).
2. Commit/push the changes to `main`. The new GitHub Actions workflow runs
   automatically on that push, or use **Actions → Kinetiq Unified Module
   Catalogue → Run workflow**.
3. The workflow fetches all eight repositories, runs tests, and offers a PR
   called **Sync Kinetiq unified catalogue from 8 upstream repositories**.
   Check the PR's changed package URLs/checksums before merging it into main.
   If PR creation is forbidden in repo settings, download the workflow artifact
   `Kinetiq-Unified-Catalogue` and manually copy its JSON files into Working Copy.
4. In Kinetiq-iOS add this single URL (or refresh it if already added):

   `https://raw.githubusercontent.com/Haimiya612/Kinetiq-Modules/main/repository.json`

5. Review publisher trust for the updated repository and test installation on
   the device. A listed candidate is **not automatically compatible**.

## What the catalog does

| Upstream | Catalogued as | Install in current Kinetiq runtime? |
| --- | --- | --- |
| Haimiya612/Kinetiq-Modules | V3 video ZIP | Candidate (existing packages preserved) |
| kas021/Synthetiq-Modules | Player ZIP packages | Candidate; actual V3/runtime compatibility unverified |
| kas021/Module-Testing-PL | Player test ZIPs | Unique IDs only; experimental |
| kas021/Testing-Modules-1-2-3-4 | Player test ZIPs | Unique IDs only; experimental |
| Synthetiq-HQ/synthetiq-manga-sources | JS manga manifests | Metadata only: requires dedicated manga runtime |
| kas021/AROKI-Connectors | Signed JSON connector manifests | Metadata only: requires native adapter + signature validation |
| kas021/Testing-Modules-AR | AROKI testing manifests | Metadata only: requires adapter + signature validation |
| kas021/AnyGo-Sources | JSON source definitions | Metadata only: requires source-specific adapter |

`repository.json` is the existing Kinetiq `schemaVersion: 1` format, and lists
*only video ZIP candidates* with original module IDs, identity fields, package
URLs, and SHA-256 checksums. `catalog/unified.json` is **generated by the GitHub Actions sync** and records
**every source entry**, including duplicates and formats not yet supported by
the app. It is not included as a fake or empty placeholder in the ZIP.

## Updating & safety

- The eight upstream indexes are fetched fresh with `node scripts/sync-unified.mjs`.
- Daily scheduled GitHub Actions propose changes as a PR, not an unreviewed commit.
- Existing video modules belong in `catalog/local-modules.json`; it is the
  locally owned source-of-truth. Add your next original module there, then sync.
- Production Synthetiq packages take precedence over duplicate testing IDs.
  Unique testing modules remain clearly identifiable and require verification.
- No upstream code is executed during index generation; source ZIPs are never
  downloaded or modified. SHA strings are copied from upstream metadata, not
  independently checked against ZIP bytes in this environment. Kinetiq itself
  checks the SHA-256 of each package after downloading it.
- Synthetiq's `minAppVersion` refers to Synthetiq Player, **not Kinetiq**. The
  merger keeps it as provenance data instead of incorrectly applying it as a
  Kinetiq compatibility gate.
- Original source URLs, module IDs, and checksums are preserved. Upstream
  signatures are **not** transferred or presented as Kinetiq signatures.
- All upstream scripts and package contents remain independently subject to
  permission, privacy, content rights and runtime security review.
- Avoid using Trust All for upstream modules until you have reviewed their
  publisher and their changes. GitHub availability is not authenticity.
